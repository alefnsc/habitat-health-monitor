# Food catalogue: items and sources

Generic foods in the style of long-shelf-life space food. These are not NASA menu items, and NASA publishes no nutrient table for individual flown items (none was found).

- Item list: `data/food/items.csv` (31 items, USDA FoodData Central SR Legacy, no Branded records, no brand names).
- Catalogue: `data/food/catalog.json`, generated by `tools/food/build_catalog.py` from the bulk CSV download. It is marked synthetic: values are database values for generic foods, not measurements of the item eaten.
- Check: `python tools/food/check_against_bulk.py --catalog data/food/catalog.json --bulk-dir <SR Legacy CSV folder>` prints "all equal" when the catalogue matches the bulk files.
- Serving sizes are FDC portions or marked "team-chosen" in the `serving_source` column. Fluid per serving is a team-chosen convention (1 cup = 240 mL), never computed from grams.
- Not reported by the source means null, shown as "not reported", never as 0.
- Adding a food (D44): `python -m tools.vault run -- python -m tools.food.fdc search "<words>"`, then `... fdc add <fdc_id> --id <slug> --category <c> --serving-g <g> --serving-label "<text>"`. Foundation and SR Legacy only. `add` appends one row here and one item to the catalogue; the other items do not change. Without `--serving-g` it lists the FDC portions. A demo hub loads the new food after a restart.
- Provenance of added foods (known gap, D44 review). The catalogue header (`generator`, `generated_at`, `fdc_release` "SR Legacy 04/2018") describes the bulk build only; it is not updated by `fdc add`. Each added item carries its own `values_via: "FDC API"` and `accessed_at` instead, and a Foundation item comes from a later FDC release than the header names. `add` refuses brand-named records (Fast Foods and Restaurant Foods categories, brand names in capitals) and a catalogue the hub would not load.
- Rebuild and check after an add. `build_catalog.py --bulk-dir ...` rebuilds every row of `items.csv` from the bulk files, added rows included; the rebuilt items lose `values_via` and `accessed_at`, and a Foundation row needs the Foundation bulk folder as a second `--bulk-dir`. `check_against_bulk.py` checks every item, added ones included, and reports "not in the bulk files" for a Foundation item unless that folder is given.
- Pack labels (D44): `python tools/food/qr_labels.py --catalog data/food/catalog.json --out var/food-labels.html` prints one QR code per item with the text `hhm-food:<item-id>`. The food screen's "Scan pack" button, or the typed code, picks that food; the crew still logs the meal.

## Text for the submission

(For S13 and S14; N11a/S14 can lift the DATA_SOURCES.md entries as they stand.)

**DATA_SOURCES.md entry: USDA FoodData Central.** Nutrient values for 31 generic shelf-stable foods come from USDA FoodData Central, CC0 1.0, credit requested: "USDA FoodData Central". Release used: SR Legacy, April 2018, CSV bulk download (`FoodData_Central_sr_legacy_food_csv_2018-04`, https://fdc.nal.usda.gov/download-datasets/). No Branded records are used. The values are copied unchanged, one FDC id per item, and `tools/food/check_against_bulk.py` checks them against the downloaded files.

**DATA_SOURCES.md entry: NASA nutrition documents.** Rule values for sodium, iron, fluid and calcium come from NASA JSC-67378 Rev 1 (Nutritional Requirements for Exploration Missions up to 365 days), a NASA program document, not NASA-STD-3001. The vitamin D floor comes from NASA-STD-3001 Volume 2 Rev F, Table 7.1-2. The sodium watch and act bands come from the superseded 2005 table JSC-E-DAA-TN71711 and are labelled as a historical operating band. Each food rule shows its source reference and page.

**NASA Data field (one sentence).** Without JSC-67378 and NASA-STD-3001 the food screen would have no reference values or rule sources to judge against.

**One sentence for S13.** The monitor also lets a crew member log meals from a catalogue of generic foods, adds the day's nutrients to the same status board logic, and shows the NASA reference values beside them, as a supporting domain next to the six primary indicators.

**Limits to state.** Nutrient values are database values for generic foods; portions are the catalogue's servings; reference values are population references from NASA documents, not personal targets; training work is shown in kJ beside food energy in kcal and is never converted or compared.
